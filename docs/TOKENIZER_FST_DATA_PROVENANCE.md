## Missing POS Ambiguity Batch `0156`

The runtime POS audit found 246 source-POS hints absent from otherwise valid
runtime analyses. Patch `0156-add-missing-c2-noun-homograph-readings.patch`
adds 80 reviewed C2 noun readings for surfaces already analyzed primarily as
verbs, including `கதை`, `அடை`, `உடை`, `குடை`, `ஆடவை`, and `கிறி`. It does
not remove or retag any verb/function analysis. The mismatch count falls to
166, and isolated-token ranking prefers the nominative noun over a zero-marked
imperative while preserving both analyses.

The current signature audit enumerates all 41,482,537 upper analyses and proves
one inverse/forward surface round trip for every one of the 4,493 exact raw-tag
patterns, with zero missing representatives and zero failures.

## How the Tokenizer Uses the FSTs

`TamilMorphTokenizer` first separates Tamil words, Latin words, numbers and date-like spans, punctuation, and symbols. Only Tamil words are sent to `FlookupAnalyzer`. Non-Tamil spans are preserved as single surface tokens with `fallback="surface"`.

For model training and exact reconstruction, `StructuredReversibleCodec` is
the authoritative layer. Its single stream uses `<WORD_START>` before analyzed
words and direct `<BYTE_XX>` tokens for whitespace, punctuation and unknown
material. The rc5 grammar removes `<WORD_END>`, `<BYTE_SPAN_START>` and
`<BYTE_SPAN_END>` because their boundaries are derivable. The HTTP API returns
that global stream and its token IDs without trimming the input; per-word
records remain diagnostic metadata.

`FlookupAnalyzer` in `tamil_morph_tokenizer/fst.py` calls `flookup` separately for each configured model and merges all recognized analyses by surface word.

The copied full generated surface dictionary is broader than the runtime FST analyzers. It includes direct lexical-source entries plus FST-generated forms, so a dictionary hit does not guarantee that one of the runtime `.fst` models can analyze the same surface. For tokenizer/root checks, prefer `lemma_dictionary.txt`: it excludes generated inflections such as `மரங்களிலிருந்து` and `படித்தான்`, and also excludes sandhi-linker prose variants such as `எனக்` and `ஊராட்சித்`.

Tokenizer behavior intentionally does not hide FST coverage gaps with ad-hoc supplemental analyses. If new words need semantic morphology, the preferred fix is to classify the root/lemma into the appropriate FST noun, verb, or adjective generation path in the source Solmaalai/ThamizhiMorph data and refresh the copied runtime FSTs and generated word lists. Use `scripts/audit_morph_coverage.py` and `scripts/audit_source_fst_gaps.py` to find Tamil spans and source-backed lemmas that currently fall back. The morphology audit writes true grapheme/unresolved gaps to `outputs/morph_coverage_gaps.csv` and non-grapheme Tamil fallback rows to `outputs/morph_fallbacks.csv`.

`analysis.py` parses each analysis and maps FST tags to readable morphology tokens, for example:

```text
மரம்+noun+pl+abl
=> மரம் <POS_NOUN> <NUM_PL> <CASE_ABL>

மரம்+noun+pl+nom+add
=> மரம் <POS_NOUN> <NUM_PL> <CASE_NOM> <CLITIC_ADD>

படி+verb+fin+sim+strong+past=த்+3sgm=ஆன்
=> படி <TENSE_PAST> <PERSON_3SG_MASC>
```

The exact raw tags remain in the selected analysis and reversible signature.
The public sequence omits derivable verb/POS, finiteness, complexity and
strength labels while retaining specific semantic features.

All analyses are preserved on each `TokenizedWord`. The surface remains in
`TokenizedWord.surface` and is not repeated in the analyzed model-token list.
The default `mode="compact_ambiguity"` emits the longest shared semantic prefix
once, followed by complete residual readings separated with `<READINGS>` and
`<ALT>`. Different lemmas remain inside their respective readings rather than
using dynamic composite or parallel candidate tokens. `mode="best"` chooses one `best_analysis` for token-count comparisons,
with common noun readings preferred in close ties such as locative over
ablative/sociative analyses. `mode="all_analyses"` uses the same reading grammar
without factoring the common prefix or repeating the surface.

At the record layer, unknown or unanalyzed Tamil words retain their surface and
`fallback="unknown_tamil_surface"` diagnostic. In the independently decodable
rc8 codec, ordinary unknown Tamil is represented by `<WORD_START>` plus fixed
`<TAMIL_GRAPHEME_...>` tokens. The 378-token alphabet is generated from public
released lexical material and regular Tamil orthography, not experiment test
text. Whole-span UTF-8 bytes remain the escape for unseen, malformed, or
mixed-script graphemes. The tokenizer-level
`unknown_tamil_fallback="grapheme"` mode remains available for record-oriented
diagnostics.

A small lexical-special layer prevents common postpositions such as `க்குள்` from splitting into graphemes, and exposes overrides or semantic supplements through `semantic_special` and `special_handling`. A narrow suffix heuristic can recover simple case morphology for unknown Tamil words with common suffixes such as `இந்தியாவை -> இந்தியா <CASE_ACC>`, marked with `fallback="suffix_heuristic"`.

`TokenizedWord.token_count`, `TokenizedWord.ambiguous`, and `TamilMorphTokenizer.token_table()` provide compact article/table-oriented views over the same records.
